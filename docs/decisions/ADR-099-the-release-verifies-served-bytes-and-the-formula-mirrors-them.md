# ADR-099 — the release verifies served bytes, and the formula mirrors them

Status: **accepted** · 2026-10-27 · narrows ADR-098 ruling 3

Affects: `.github/workflows/publish.yml`, `scripts/build-sea.mjs`,
`scripts/verify-release-asset.mjs`, `Formula/simt-dev.rb`

## Context

ADR-098 ruling 3 made determinism the release contract in its strongest form: the
same tree builds byte-identical assets on any host, so the tag workflow rebuilds
each asset and fails when its checksum is not the one `Formula/simt-dev.rb` in the
tagged tree promises. The v0.6.0 tag proved the strong form false. The CI-built
`linux-x64` asset hashed to `809dcda7…` while the same tree built on a darwin host
hashed to `b55bffc2…` — and the local rebuild is reproducible, so the difference is
the host, not the tree. The SEA blob is generated by a node running on the build
host, and a darwin-generated blob and a linux-generated blob of the same tree
differ. A check comparing CI bytes against locally-built committed checksums can
therefore never pass, and keeping it means every release fails at tag time for a
reason no tree change can fix.

The same run surfaced the second defect in the arrangement: all three targets built
on `ubuntu-latest`, but darwin binaries are finished with `codesign`, which exists
only on macOS. The darwin jobs never ran anywhere before v0.6.0 — v0.5.0 predates
the binary channel — so the runner assignment was never exercised either.

## Ruling

1. **Each target builds on its native runner.** `darwin-arm64` and `darwin-x64` on
   `macos-14`, `linux-x64` on `ubuntu-latest`, with `fail-fast: false` so one
   target's failure no longer cancels the others. Determinism is per host family —
   the same tree rebuilt on the same OS family hashes identically — and the matrix
   is what makes that claim checkable instead of aspirational.

2. **The release checks upload integrity, not cross-host equality.** After uploading
   each asset, the workflow downloads what GitHub serves for it
   (`scripts/verify-release-asset.mjs`) and fails when the served sha256 is not the
   one the build just wrote. A torn or clobbered upload graduates into a release
   nobody can detect any other way; the tap installing bytes whose checksum refuses
   them is exactly that failure arriving on somebody else's machine.

3. **The committed formula is a mirror, refreshed after the release moves it — never
   a prediction.** A `sync-formula` job renders `Formula/simt-dev.rb` from the
   served bytes with `scripts/release-formula.mjs` and commits it to `main` when it
   changed. A re-run that finds the mirror current exits quietly, and a formula
   that already names a newer version is left alone, so an older tag can never
   rewrite a newer mirror. The tap push (`publish-channels.yml`) already renders
   from served bytes, so it was correct by construction throughout; this closes the
   loop for the in-repo copy.

## Consequences

- **The v0.6.0 equality check is gone, and its premise with it.** Nothing in the
  release compares bytes built on different hosts. The `build-sea.mjs` header no
  longer claims cross-host byte-identicality.
- **The formula in a tagged tree is the previous release's mirror, and that is
  stated rather than hidden.** Between the tag and `sync-formula`'s commit it names
  the served bytes of the last release, which is what makes it a mirror and not a
  promise.
- **`verify-release-asset.mjs` is runnable by hand.** It takes `--version` and
  `--target` and answers whether the release serves what a build of this tree
  wrote — the same question the workflow asks, askable from any checkout.

## Rejected

- **Generating one blob on one host and sharing it across targets.** It would make
  the three assets share a blob while their node bases still differ per target, so
  cross-host equality would still fail at the base — the part this repository does
  not build. Sharing would add artifact plumbing to preserve a comparison the
  release no longer makes.
- **Committing the formula from the tag before the assets exist.** That restores the
  prediction in a new place: the committed checksums would again be bytes no
  download has served, and the first thing that reads them (the tap) would read a
  promise instead of a record.
