# Module and MCP reference

Rendered from the command spec by `simt docs commands --yes`; do not edit by hand.

| Module | CLI commands | Read-only MCP tools | When an agent should use it |
| --- | --- | --- | --- |
| **Task Brief** | `simt brief "<task>"`, `simt work packet --input <file>` | `brief`, `work_packet` | First call on every task to get task kind, commands, ranked files, tests, ADRs, skills, and lessons in <= 2 KB; `work packet` when the packet must prove its units are cited |
| **Code Graph & Retrieval** | `simt index [--open] [--search <task>] [--embed]`, `simt index overlay --input <file>`, `simt map --task "<task>"`, `simt impact <file|symbol>`, `simt tests <path> [--cochange]  |  --run [--changed]`, `simt gate --changed` | `index_overlay` | Before editing to rank files (`map`), trace blast radius (`impact`), run only diff-affected tests (`gate --changed`), or ask the open cache (`index --search`) |
| **Knowledge & Governance** | `simt why [<subject>]`, `simt rules list [--root <path>]`, `simt rules show <id>`, `simt rules why <id|ADR-NNN> [--all]`, `simt decide lint`, `simt decide new "<title>" --yes`, `simt knowledge why <claim-id> --claims <file> [--limit <n>] [--page <n>]`, `simt knowledge rank --input <file> --query "<question>"`, `simt knowledge impact --input <file> --refs <ids>`, `simt knowledge derivations --input <file>`, `simt knowledge debt --input <file>`, `simt knowledge sections <file.md>`, `simt knowledge export --input <file>`, `simt knowledge import --input <file>` | `rules_list`, `rules_why`, `knowledge_why`, `knowledge_export`, `knowledge_import` | Before touching governed files (`why`), when ranking evidence or asking what a change puts in question, or when moving claims between repositories as data |
| **Verification** | `simt verify plan --input <file>`, `simt verify select --input <file>`, `simt verify status --input <file>`, `simt verify contracts --input <file>`, `simt verify documents --input <file>`, `simt verify procedures --input <file>` | `verify_plan`, `verify_select`, `verify_status`, `verify_contracts`, `verify_documents`, `verify_procedures` | Before choosing checks, when closing recorded obligations, or when checking a generated document, a procedure or a set of obligation results |
| **Actions & Adapters** | `simt action status --journal <file>`, `simt action review --input <file>`, `simt adapter check --input <file>` | `action_status`, `action_review`, `adapter_check` | Before executing an operation: read the journal state, review the bundle, and validate an adapter descriptor as data |
| **Skills & Disclosure** | `simt skills index`, `simt skills brief --task "<task>"`, `simt skills show <name>`, `simt skills why <name>`, `simt skills find <query>`, `simt skills install <name> --yes`, `simt skills compile [<name>]`, `simt skills eval [corpus]`, `simt graph lint [--spec agentskills]` | `skills_index`, `skills_brief`, `skills_show`, `skills_why`, `skills_find` | When a task requires domain workflows or reference docs without blowing the session token budget |
| **Memory & Lessons** | `simt lessons list`, `simt lessons review <id> --yes`, `simt lessons discover --input <file>` | `lessons_discover` | After fixing a failing test/gate or hitting a hook denial, to inspect or promote reusable failure-to-fix lessons, or to deduplicate discovery candidates |
| **Work & Plans** | `simt work inspect`, `simt work schedule --input <file>`, `simt work handoff --input <file>`, `simt work resume --input <file>`, `simt work graduate --input <file>`, `simt plan status`, `simt plan next [<id>] [--tier <name>] [--wave <name>] [--lane <name>]`, `simt plan done <id> [<sha>] --yes`, `simt slice start <id> --yes  |  -- "<text>"`, `simt slice finish <id> --yes`, `simt lease [<paths>] --session`, `simt pr-body [--base <ref>]`, `simt status [--line]`, `simt undo --yes` | `work_inspect`, `plan_next`, `plan_done`, `pr_body` | When describing a repository's work, sequencing ready tasks, resuming a handoff, or executing a phased plan row by row |
| **Adoption & Projection** | `simt init [path]`, `simt doctor [--fix]`, `simt check`, `simt sync --yes`, `simt workspace upgrade --yes` | `doctor`, `check` | When adopting a repo, diagnosing stack/config health, or verifying zero drift before commit |
| **Dual Gates & Evidence** | `simt hooks install --yes`, `simt hooks status`, `simt hooks run <event>`, `simt agent-hooks install --yes`, `simt agent-hooks status`, `simt agent-hook <event> --harness`, `simt evidence`, `simt evidence check <msg-file>`, `simt evidence validate --input <file>` | `evidence_validate` | When installing git/agent hooks, running gates manually, or validating a test claim and its chain of custody before committing |
| **Context & Harnesses** | `simt tokens [--repos] [--session]`, `simt harness detect [--user]`, `simt harness loaders [--table]`, `simt workspace install --yes`, `simt workspace share` | — | When auditing startup token cost across harnesses (`claude`, `codex`, `cursor`, `opencode`, `antigravity`, `copilot`, `deepseek`) or deduplicating workspace rules |
| **Workspace & Benchmarks** | `simt workspace compare`, `simt bench mine --yes`, `simt bench run --yes`, `simt bench report [--compare a b]`, `simt bench ablate --yes`, `simt bench probes --yes`, `simt bench replay --input <file>`, `simt bench calibrate --input <file>`, `simt bench compat --input <file>`, `simt bench corpus --input <file>`, `simt bench world --input <file>`, `simt local doctor [--allow-remote]`, `simt review [--local]`, `simt distill <skill|doc>` | `compare` | When auditing an entire multi-repo estate, measuring rule uplift/cost, replaying an outcome, calibrating autonomy, or probing local model endpoints |

The command names and their flags are generated in [../commands/index.md](../commands/index.md);
this table is the shape of the surface, not its contract.
